# 整理方針

1. `004-organize-fork` で既存の設計・仕様変更を保持する。
2. 内側の元作業ツリーの docs/firmware/web/tools/.github と hardware/rev1 を外側へ集約する。同名の現行KiCadを上書きせず、旧CADは hardware/archive/ へ保全する。
3. READMEを入口にし、既存の利用案内と原作者への参照を保持する。旧パスを使う仕様は移設先へ更新する。
4. 作業コピー・一時生成物・マシン固有ディレクトリを除外する。ソフトウェアの機能や現行基板の内容は変更しない。
5. 正規CAD全13ファイルのハッシュ、移設したソフトウェアの内容、シェル構文、公開対象を確認する。
6. 既存開発履歴に成果をコミットし、内容を取り込んだ元mainの履歴を統合する。既存main/masterを上書きせず、フォークの作業ブランチへpushして識別子を照合する。

Windows利用者向け書込ツールは製品の一部として維持する。WSL用シェルの改行はLFへ統一する。基板の製造上の残課題は003で継続する。
