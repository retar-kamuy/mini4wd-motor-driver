# Feature Specification: リポジトリ整理とフォークへの公開

**Feature Branch**: `004-organize-fork`
**Created**: 2026-11-12
**Status**: Validated
**Input**: 元プロジェクトから開発してきた内容を整理し、retar-kamuy/mini4wd-motor-driverへpushする。

## User Scenarios & Testing

### User Story 1 - 設計とソフトウェアを迷わず探す (Priority: P1)

開発者は、基板設計、ファームウェア、Webアプリ、資料の正本を一つの入口から探せる。

**Why this priority**: 入れ子の作業コピーと正規設計の混同を防ぐ。
**Independent Test**: 初めて取得した開発者がREADMEから各正本に到達できる。
**Acceptance Scenarios**:
1. **Given** 整理したリポジトリ、**When** READMEを読む、**Then** 正規設計と履歴資料の位置が分かる。
2. **Given** 既存の未コミット変更、**When** 整理する、**Then** 基板・ソフトウェア・資料の変更が失われない。

### User Story 2 - 元プロジェクトとの来歴を保つ (Priority: P1)

保守者は原作者のプロジェクトと今回の開発内容の関係を確認できる。

**Why this priority**: 元資料と変更内容を辿って保守するため。
**Independent Test**: 来歴文書と公開履歴から元プロジェクトと開発版を確認できる。
**Acceptance Scenarios**:
1. **Given** 異なるローカル履歴、**When** 公開する、**Then** 元履歴と現在の開発履歴を参照できる。
2. **Given** 未完了の基板設計、**When** 公開内容を読む、**Then** 製造未承認であることと残課題が分かる。

### User Story 3 - 自分のフォークで開発を継続する (Priority: P1)

利用者は整理済みの成果を自身のフォークから取得できる。

**Why this priority**: ローカルだけに存在する作業を共有・継続するため。
**Independent Test**: フォークの公開ブランチとローカルの確定版が一致する。
**Acceptance Scenarios**:
1. **Given** フォークへの書込権限、**When** pushする、**Then** 整理した成果が作業ブランチに存在する。
2. **Given** 既存mainとmaster、**When** 公開する、**Then** 既存ブランチの履歴を上書きしない。

### Edge Cases

- 認証や書込権限が不足した場合は、確定したローカル成果と再開方法を記録する。
- 同名の旧設計がある場合は、現行設計を優先し、旧版を来歴資料として識別する。
- 一時ファイルや環境固有データは作業領域に保全し、公開物から除外する。

## Requirements

### Functional Requirements

- **FR-001**: 正規基板、ファームウェア、Webアプリ、資料の位置と用途を案内する。
- **FR-002**: 内外の作業ツリーの既存変更と原作者の来歴を保全する。
- **FR-003**: 一時検証データ、環境固有ファイル、認証情報を公開物に含めない。
- **FR-004**: 整理の前後で正規設計の内容と製造未承認状態を維持する。
- **FR-005**: 整理方針、移設対応、確認結果を記録する。
- **FR-006**: 指定フォークへ作業ブランチをpushし、公開版の識別子を確認する。
- **FR-007**: 既存main/masterへの強制pushおよび既存履歴の削除を行わない。

### Key Entities

- **正規成果物**: 現在の基板・ソフトウェア・仕様と資料。
- **履歴資料**: 元プロジェクトと過去設計の参照用データ。
- **公開版**: ブランチ、確定版識別子、確認結果。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 全ての主要成果物への案内がREADMEに存在する。
- **SC-002**: 正規設計の整理前後の内容差が0件である。
- **SC-003**: 公開対象に入れ子のGit管理領域と既知の一時作業フォルダが0件である。
- **SC-004**: 公開ブランチの識別子とローカル確定版が一致する。
- **SC-005**: 元の公開履歴と既存開発履歴の双方を公開版から辿れる。

## Assumptions

- 作業ブランチへのpushは本依頼で承認されている。
- この整理には基板の回路・配線変更や製造準備完了の認定を含めない。
- 利用者向けの既存Windows書込ツールは製品機能として保全し、開発作業はWSLのシェルで行う。
