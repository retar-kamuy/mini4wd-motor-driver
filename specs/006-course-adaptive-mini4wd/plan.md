# Implementation Plan: コース適応型ブラシレスミニ四駆

**Branch**: `006-course-adaptive-mini4wd` | **Date**: 2026-11-21 | **Spec**: [仕様006](spec.md)

## Summary

市販シャーシに車載センサーと専用制御基板を搭載する。レーンチェンジのある1コースを低速で全レーン巡回して学習する。アプリがログから区間マップと目標速度案を作り、利用者が確認・調整して車体に適用する。走行中の位置照合、速度制御と駆動停止は車体が担当し、アプリ接続の喪失時は駆動を切る。

趣味用の車載ブラシレス基板を初版から設計する。ROCKET-RC MINI 1525 5500KVと2S LiPoを評価候補に、車載基板で初回通電・停止・低速走行を確認し、必要に応じて改版する。基板の発注前は回路・配線・部品・製造データの確認に絞り、実車でしか確認できない搭載・負荷・熱は初版の評価で記録する。候補は[電源設計方針](power-architecture.md)、性能の目安は[駆動性能の机上比較](drive-performance.md)、開発経路は[調査記録](research.md)に記す。

## Technical Context

| 項目 | 計画 |
|---|---|
| 言語・依存 | 車体はC++、既存Arduino系ファームウェアから記録・通信の実績を参照。アプリは既存Web UIを起点としたJavaScriptとWeb Bluetooth。採用MCU向けのSDKと版を実装開始時に固定する |
| 保存 | 車体は時刻付き走行ログと適用済み設定を保持。アプリは原本ログ、区間マップ、速度設定の版、比較結果を保存し、ファイルとして出力する |
| 対象環境 | BLE対応PCと対応ブラウザーを初回の操作端末とする。車体は1台、受入コースは1つ、走行ごとに開始レーンを固定する |
| 検証 | 記録データの再生、駆動系ごとの机上・台上検査、BLE切断と再接続の試験、実走、製造資料の照合 |
| 性能 | 仕様SC-001〜006を適用。減速に使える時間から位置判定・制御の遅延予算を割り出す。通信喪失から駆動停止までの上限はテスト前に決めて実測する |
| 制約 | コース側に追加物なし。車載カメラは比較候補。車体収納、重量、消費電力、JLCPCBの実装条件を基板確定前に照合する |

## 実装順序と着手条件

1. **車載初版の設計** — 駆動、停止、BLE、計測に必要な回路と取付を設計する。回路・基板・部品・製造ファイルを照合してJLCPCB提出資料を作る。メーカー仕様で決まらない実機条件は、接続前の確認項目に記録する。
2. **初版PCB発注後のソフトウェア実装** — 基板の発注後にSpec Kitでソフトウェアの仕様・計画・タスクを整理する。Webアプリは既存の `web/`、特に `web/index.html` のBLE接続と操作画面を参照する。車載ファームウェアは確定した端子・信号を使い、ログ、区間照合、速度設定、停止処理を実装する。
3. **初版の立上げ** — 車載初版で電源と駆動禁止を確認し、接続・電圧条件を確定してから電流制限下で回転、発熱、停止、搭載を確認する。
4. **実走と改版** — [検証手順](quickstart.md) に沿って低速から評価し、同一ブラシレス車で区間制御無効・有効を比較する。問題は測定記録から調整や改版へ反映する。
