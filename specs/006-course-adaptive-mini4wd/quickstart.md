# 検証手順

この手順は006の実装と試作機の準備後に実施する。計画時点の完了記録ではない。

## 前提

- レーンチェンジがあり、同じ開始レーンへ戻るまでに全レーンを通るコースを選ぶ。物品や機器をコースへ設置しない。
- 車体構成と電池条件を記録し、駆動・停止と通信喪失時の反応を先に台上で確認する。
- BLE対応PCの対応ブラウザーでアプリをHTTPSまたはlocalhostから開く。実装予定のWebディレクトリをPC側で配信する例は、リポジトリルートで `python3 -m http.server 8000 --bind 127.0.0.1 --directory web/course-adaptive` を実行して `http://localhost:8000/` を開く。
- 同じ開始位置・レーン・走行方向、計時方法、無効の判定、短縮幅と比べるばらつきの算出方法を試験前に記録する。観察や計時は車体制御へ入力しない。

## 手順

1. **学習** — アプリを接続して低速走行を開始する。全レーンを巡回し、停止後にログを取得する。加速度、角速度、回転数と周回時刻の記録を確認する。
2. **確認と適用** — 各区間の初期速度案を確認し、1区間以上を変更する。適用前後でアプリと車体が報告する設定版を確認する。受領中断時も前の適用済み版を確認できること。
3. **再走行** — 全レーンを巡回し、実際のレーン順序とログを照合する。少なくとも合意済みの1区間へ入る前に指令が変わり、適用済み速度設定と一致することを確認する。
4. **異常** — 未接続で開始を試す。接続中の位置未確定では学習走行以下へ制限し、台上で接続を切ると駆動を切り自然減速することを確認する。再接続だけでは再始動しないことを確認する。
5. **タイム比較** — 同一ブラシレス試作車で区間制御無効・有効の2条件について、同数の全レーン巡回で各5有効周以上を収集する。車体・電源・駆動条件をそろえ、全試行を記録する。有効設定が無効時より速く、差が事前に把握したばらつきを上回り、コースアウト0件であることを確認する。プラズマダッシュ車との比較は本試験の必須条件ではない。[駆動性能の机上比較](drive-performance.md)で定めた負荷点と換算速度は設計記録に残す。
6. **製造資料** — 回路図・PCB・Gerber・ドリル・BOM・CPL・検査条件を同一版にそろえ、ERC/DRC、回路図とPCBの照合、業者の部品照合・実装プレビュー・DFM回答を記録する。

計測・判定の各項目は [データモデル](data-model.md) と [車体とアプリの契約](contracts/vehicle-app.md) を参照する。
