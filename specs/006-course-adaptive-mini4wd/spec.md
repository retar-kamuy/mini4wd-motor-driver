# Feature Specification: コース適応型ブラシレスミニ四駆

**Feature Branch**: `006-course-adaptive-mini4wd`

**Created**: 2026-11-21

**Status**: Ready for planning

**Input**: 005のブラシレス化を土台に、車体だけでコースを学習し、区間に合わせてモーターを制御して高速・安定走行を目指す。通常のミニ四駆より明らかに遅くなる設計を避け、プラズマダッシュ級以上を開発目標に置く。利用者は比較用のミニ四駆を所有していないため、ブラシ付き車との実走比較は必須にしない。003で経験したXIAOの調達・実装上の制約を踏まえ、専用基板を開発する。ブラシ付き試作の有用性も比較し、採用する場合はブラシレス版への再設計・再評価を抑える。

## Clarifications

### Session 2026-11-21

- Q: 初回試作の合格条件として、どの種類のコースで学習と周回タイムの短縮を実証しますか? → A: レーンチェンジを含む1コースで、全レーンを巡回する走行を実証する。
- Q: 初回試作の区間別速度制御は、スタート後にスマートフォンやPCを接続せずに走れることを必須としますか? → A: スタート後もアプリとの接続を維持する。通信が途切れたら駆動を切り、自然減速する。
- Q: 初回試作では、学習走行のあとに各区間の目標速度を誰が決めますか? → A: システムが目標速度の初期案を作り、利用者がアプリで確認・調整して適用する。

### Session 2026-11-22

- 個人の趣味用として、初版から車載ブラシレス基板を作る。専用ベンチ基板やブラシ付き先行試作基板を製造する工程は設けない。初版の車載基板で初回通電、停止と低速走行を確認し、必要な変更は改版で反映できる。ファームウェアとWebアプリは初版PCBの発注後にSpec Kitで進める。Webアプリは既存の `web/` を参考にする。

## User Scenarios & Testing

### User Story 1 — コースを学習する (Priority: P1)

利用者は低速で走らせ、車体で記録した動きと回転数から、直線、カーブ、坂などの順序と周回内のおおよその位置を把握できる。

**Why this priority**: 区間の手前で速度を変えるには、次にどの区間へ入るかを把握する必要がある。

**Independent Test**: コースに機器や目印を追加せず、レーンチェンジのある1コースで全レーンを低速で巡回して区間マップを作り、別の走行でレーン遷移を含む区間の並びを照合する。

**Acceptance Scenarios**:

1. **Given** 未学習の周回コース, **When** 利用者が低速で学習走行する, **Then** 車載計測値と時刻が記録され、周回内の区間順序と推定距離を確認できる。
2. **Given** 保存済みの区間マップ, **When** 同じコースを再走行する, **Then** 車体は記録と現在の計測を照合し、区間または位置未確定の状態を示す。

### User Story 2 — ブラシレス車で周回タイムを縮める (Priority: P1)

利用者は、学習結果から生成された区間ごとの目標速度案をアプリで確認し、必要に応じて調整して適用する。区間別速度制御を開始したら、走行中もアプリとの接続を維持する。安定して完走し、通常のミニ四駆より明らかに遅くなる設計を避け、プラズマダッシュ級以上の走行性能を目標とする。

**Why this priority**: ブラシレス化とコース学習を、周回タイムで評価する。

**Independent Test**: 同一ブラシレス試作車を同じコースで区間制御無効・有効の両条件で走らせ、完走率と周回時間を比較する。ブラシ付き車との速度関係は設計上の目標・制約であり、直接比較の合格条件には含めない。

**Acceptance Scenarios**:

1. **Given** 学習済みのコースとブラシレス車, **When** 車体が減速対象の区間に近づく, **Then** 区間に入る前に速度指令を調整し、指令と走行結果を記録する。
2. **Given** 車体が区間を特定できない, **When** 区間に応じた高速指令を出そうとする, **Then** 学習走行以下の速度設定に戻る。
3. **Given** アプリを接続して区間別速度制御で走行している, **When** アプリとの通信が途切れる, **Then** 駆動を切って自然減速し、再接続後も利用者が明示的に走行開始を指示するまで再始動しない。
4. **Given** アプリが未接続である, **When** 利用者が区間別速度制御を開始しようとする, **Then** そのモードでの走行を開始しない。
5. **Given** 学習済みのコースに対する目標速度の初期案がある, **When** 利用者がアプリで案を確認し、必要に応じて調整して適用を指示する, **Then** その設定が次回の走行で使われる。適用を指示するまでは、初期案を走行に使わない。

### User Story 3 — 開発経路を選び、専用基板を試作する (Priority: P2)

開発者は、ブラシレス版から始める案と、市販ミニ四駆用ブラシ付きモーターで先に試作する案を比較し、短い手戻りで走行評価と製造依頼に進める経路を選ぶ。

**Why this priority**: 先行試作に費やす工数と、ブラシレス版で減らせる手戻りを比較するため。

**Independent Test**: 両経路の評価項目、共通化範囲、移行時の再評価項目を比較し、選定理由を確認する。製造業者が固定した同一版の資料から見積と製造・実装条件を回答できることも確認する。

**Acceptance Scenarios**:

1. **Given** 二つの開発経路, **When** 設計を固定する前に比較する, **Then** 調達、試作工数、先に検証できる機能、移行時の再設計・再評価を記録し、ブラシ付き試作の採否を決める。
2. **Given** ブラシ付き先行試作を選んだ, **When** ブラシレス版へ移行する, **Then** 共通の成果物と試験結果について成立条件を照合し、差分に必要な再評価を特定できる。
3. **Given** 固定した専用基板の設計版, **When** 製造業者が資料を確認する, **Then** 製造条件、部品調達、実装、検査条件を特定し、未解決事項を回答できる。

### Edge Cases

- 似たカーブの繰り返しやレーンチェンジにより、複数の位置候補が残る。
- 空転・ジャンプ・壁との接触により、回転数から推定した距離と実際の移動距離がずれる。
- コースやレーンが変わる、または記録が欠けて、既存マップを信頼できない。
- 電池電圧低下、センサー喪失、制御の再起動により、安全な速度制御を続けられない。
- 指定部品の調達や搭載が難しくなり、製造業者から代替案が提示される。

## Requirements

### Functional Requirements

- **FR-001**: 005を土台に、ブラシレスモーターのセンサー信号で転流する車両と、そのための専用制御基板を開発する。市販シャーシを使い、必要な専用取付部品や最小限の加工を記録する。
- **FR-002**: コース側への目印、機器などの追加を禁止する。車載計測で加速度、角速度、回転数、経過時刻と推定した周回時刻を記録する。区間の識別や位置推定に必要な場合は、車載カメラやその他の追加センサーを使用できる。
- **FR-003**: 記録から区間の順序、区間内の推定距離、周回の境界を含むマップを作成し、次の走行に再利用できるようにする。初回試作では、レーンチェンジのある1コースで全レーンの区間とレーン間の遷移を記録し、再走行時に照合できるようにする。区間やレーンを特定できない場合は位置未確定として記録する。
- **FR-004**: システムは学習走行の結果から各区間の目標速度の初期案を作る。利用者はアプリで案を確認・調整し、明示的に適用できる。車体は現在の計測とマップを照合し、適用済みの設定に従って区間の手前で速度指令を調整する。利用者は走行後に区間、速度指令と周回タイムを確認できる。
- **FR-005**: 初回試作の区間別速度制御は、走行開始から終了までアプリとの接続を必須とする。通信喪失時は車体側で駆動を切って自然減速し、通信復帰後に利用者が明示的に走行開始を指示するまで再始動しない。接続中に位置を特定できない、またはマップが合わない場合は学習走行以下の速度設定に戻す。異常時の停止動作は速度最適化より優先する。
- **FR-006**: 詳細設計前に、ブラシレス直行案とブラシ付き先行試作案を、調達、工数、先に検証できる項目、再設計・再評価の範囲で比較し、採否と理由を記録する。
- **FR-007**: ブラシ付き試作を選ぶ場合、車載計測、ログとマップの形式、区間推定、速度指令と安全停止の仕様、制御側の回路と取付方法、試験手順を共通化の対象とする。共通化できない項目には理由を記録する。駆動方式に依存する電源、駆動、ブレーキ、発熱、機構については、移行後の差分と再評価範囲を定める。
- **FR-008**: JLCPCBを第一の製造・実装候補として、部品の入手性と実装可否を設計固定前に確認する。同一設計版の製造データ、部品表、実装座標、検査条件を提出できるようにし、業者の受入条件と未回答事項を記録する。
- **FR-009**: ブラシレス車の区間別制御有効・無効を比較し、完走・コースアウト・周回タイムを記録する。通常のミニ四駆より明らかに遅くなる設計を避ける性能制約を設計目標とする。利用者は比較用ミニ四駆を所有していないため、ブラシ付き車との実走比較を必須受け入れ試験にしない。公開回転数を使った比較は設計参考に限定し、実走性能を実証したとは扱わない。

### Key Entities

- **走行ログ**: 車載計測値、時刻、区間推定、速度指令、周回結果。
- **区間マップ**: コースとレーンを識別し、区間順序、推定距離、周回の境界を保持する記録。
- **速度設定**: コースの各区間の目標速度と、位置未確定時の設定。生成された案と利用者が適用した設定を区別する。
- **比較試験記録**: 車両、電池状態、コース、走行条件、完走数、タイムとそのばらつき。
- **開発経路の決定記録**: 採否、共通設計、再利用する評価とその条件、移行後に再評価する差分。
- **製造パッケージ**: 固定版の製造・実装資料、検査条件、業者回答。

## Success Criteria

### Measurable Outcomes

- **SC-001**: コース側に追加物を設置せず、低速で全レーンを巡回し、加速度、角速度、回転数、周回時刻を記録する。保存したマップを使う別の走行で全レーンを巡回し、ログ上のレーン遷移が実際の走行順と一致し、合意した減速対象のうち少なくとも1区間の手前で速度指令が変わることを確認する。
- **SC-002**: 区間制御の評価では、同一ブラシレス試作車の制御無効・有効について、同数の全レーン巡回で各5有効周以上を集める。有効時の周回タイム中央値が無効時を下回り、短縮幅が事前に把握した計時・周回のばらつきを上回り、コースアウト0件であることを確認する。失敗や無効周回も記録する。ブラシ付きミニ四駆との直接比較は受け入れ条件に含めない。「通常車より明らかに遅くならない」は設計上の性能制約として扱い、回転数・トルク・ギヤ比の根拠と不確かさを記録する。実走比較がない限り、達成を実証済みと表現しない。
- **SC-003**: 未接続での走行開始、接続中の位置未確定、走行中の通信喪失、再接続を試験する。それぞれ、走行開始の拒否、学習走行以下への速度設定の制限、駆動停止と自然減速、明示的な走行開始指示までの停止維持を確認し、意図しない再始動は0件とする。
- **SC-004**: 詳細設計前に2案の比較と採否が1件記録される。ブラシ付き試作を行う場合は、各共通成果物・試験に再利用条件を付け、駆動方式の変更に伴う再評価項目を対応付ける。
- **SC-005**: 製造業者へ渡す設計版が1つに特定でき、部品調達、実装、検査に関する回答と未解決事項を追跡できる。
- **SC-006**: 学習完了後、マップ上の全区間に目標速度の初期案が表示される。試験で少なくとも1区間の目標速度を変更して適用し、次回走行のログが適用済みの設定に従うことを確認する。未適用の案が走行に使われた件数は0件とする。

## Assumptions

- 趣味用途の試作を想定する。車体のみで使える区間マップを初期目標とする。試験員による観察・計時を評価に使えるが、それらの情報を走行中の車体へ送る必要はない。
- 車載カメラや追加センサーは任意とする。採否は、区間の識別や位置推定の改善と、車体への搭載性、重量、消費電力を比較して設計計画で決める。
- 通常のミニ四駆およびプラズマダッシュは設計目標・性能下限を考えるための参照であり、利用者が比較車を所有していないため実走比較を必須にしない。ブラシレス制御有効・無効は同一試作車、同一電源・駆動条件で比較する。将来ブラシ付き比較を実施する場合は、車体、ギヤ比、タイヤ、電池状態、走行条件を記録する。
- 003はブラシ付き駆動の参考、005はブラシレス駆動と市販シャーシへの搭載の参考とする。制御アプリと専用基板はCodexが設計する。具体的なデバイス、電池、回転計測方式、共通回路の構成は設計計画で選定する。
